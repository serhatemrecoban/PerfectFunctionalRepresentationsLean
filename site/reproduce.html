Reproduce and cite

The repository preserves the toolchain and dependency baseline used for the completed case study. Reproduction does not require adapting it to a later LeanInfoTheory release.

Build all maintained modules.

Install Git, Lean's elan toolchain manager, and Python 3.11 or newer. The committed toolchain file selects Lean automatically. Use python3 if that is your system's Python command.

git clone https://github.com/serhatemrecoban/PerfectFunctionalRepresentationsLean.git
cd PerfectFunctionalRepresentationsLean
lake exe cache get --cache-from=master,legacy
python -B tools/check_public_build.py build

This builds all 56 maintained Lean modules, including tests and examples, then the default target. The gate verifies the installed dependency revisions and unchanged configuration. The cache command downloads public mathlib release artifacts; it does not download prebuilt PFR proofs.

Keep the frozen dependency baseline. Do not run lake update to reproduce this case study. A dependency upgrade is a separate reviewed task.

The lightweight entry point

lake build

The default build is intentionally lighter. Matrix, optimization, optional decoding, examples and regression modules remain separately importable. Use the all-module gate for full maintained-source validation.

Inspect the validation.

The public CI workflow starts from a fresh hosted checkout, fetches public dependency artifacts and compiles PFR from source. It checks all maintained modules, the default target, dependency revisions, forbidden proof placeholders and checkout cleanliness.

A recorded Ubuntu run passed on the public readiness source, and a separate Windows public checkout passed the all-module and default builds. The local Windows check used an already installed Lean toolchain. These checks do not claim a from-source rebuild of all mathlib dependencies.

Check the generated reference.

The PFR API contains compiler-printed types, available source docstrings and pinned source links. After installing the same build prerequisites, verify it with:

python -B tools/generate_api.py --check

This builds the selected modules, reads their elaborated Lean declarations and compares the generated pages with the checked-in reference. It adds no dependency. The faster --check-render mode verifies source identities and rendering, but does not replace this compiler-backed check. The API's documented scope excludes private machinery and tests; it is not a substitute for dependency documentation.
